# Classroom CLI Usage

Before configuring `classroom-cli`, familiarize yourself with some of its terminology and directory layout.


## Terminology and Organization

`classroom-cli` is a CLI tool and will require you to be mindful of your terminal's working directory.
Several commands use the current working directory as "input".

|Term|Definition|
|-|-|
|`course-dir`|**Course Directory.** The directory that will hold all *submission directories* of the course. Each submission directory will contain all student repositories. The name of `course-dir` can be anything. Do not place `course-dir` inside a cloud drive (OneDrive, iCloud, Box, etc.).|
|`submission-dir`|**Submission Directory.** A directory representing an assignment where all student repositories will be stored. This will share the same name as the general assignment name (not including Term Code).|

> [!TIP]
> Consider making your `course-dir` your terminal's working directory.

Assignment repositories will be named in the format:

`{TermCode}-{AssignmentName}-{StudentEmailPrefix}`

Example: `AY2027S1-Lab1-Intro-studentEmail`.

The `course-dir` folder structure will look like:

```text
course-dir
├── submission-dir
│   ├── student-repo
│   ├── student-repo
│   └── ....
├── submission-dir
└── ...	
```

As an example:
- The course dir was `BME2310-AY2027S1` (a folder somewhere on your machine)
- The `TermCode` was `AY2027S1`
- The first lab assignment was named `Lab1-Intro`
- The second lab assignment was named `Lab2-InputOutput`
- There are two students with emails `studentA@school.edu` and `studentB@school.edu`

The file structure would look like:

```text
BME2310-AY2027S1
├── Lab1-Intro
│   ├── AY2027S1-Lab1-Intro-studentA
│   └── AY2027S1-Lab1-Intro-studentB
└── Lab2-InputOutput
    ├── AY2027S1-Lab2-InputOutput-studentA
    └── AY2027S1-Lab2-InputOutput-studentA
```

### GitHub Fine-Grained Personal Access Token (PAT)

`classroom-cli` needs permission to access your private GitHub organization and student repositories.
We can give it permission by giving it a Personal Access Token (PAT).
The PAT is generated by GitHub.

There are two methods to obtaining a PAT:

1. Use the GitHub CLI tool `gh` to create the token.
2. Generate the token yourself on GitHub.com.

Method 2 is described below:

#### Creating a PAT

1. Go to GitHub.com and navigate to your user settings.

2. On the left side, select `Credentials` > `Fine-grained personal access tokens`.

3. Generate new token:

    1. Give it any name and description for your records.

    2. Set the `Resource owner` to your classroom organization.

    3. Set the expiration date. Consider setting it about a month after the end of the semester.

    4. Set the `Repository access` to `All repositories`.

    5. In the `Permissions` section:

        - In the `Repositories` tab, add the `Administration` and `Contents` permissions and set them BOTH to `Read and write`.
        - In the `Organizations` tab, add the `Members` permission and set to `Read-only`.

    6. Generate the token.

Save this token somewhere safe - it is essentially a password to your GitHub organization with limited control.

You will need this token when you run `clsrm configure`.


### Course Directory

You will need to make a directory on your local machine to contain all the different assignments, this is referred to as the `course-dir` directory (see *organization* above).

> [!CAUTION]
> Do not make this folder in a cloud storage drive like OneDrive, iCloud Drive, Box, etc.

### Student Roster

You must procure a roster of students as a `.csv` file with headers "email" and "github_username".
- `email` will be used to name student repos - only text before the `@` will be used in the repo name.
- `github_username` is the student's GitHub username.

`classroom-cli` will create student repositories by appending their email prefix to the repository assignment name.

Place this roster file somewhere where it won't move. When you configure `classroom-cli` with the command: `clsrm configure`, you will need to provide the system path to this file.

### Configuration

The CLI tool has an interactive configuration wizard by running:

```bash
clsrm configure
```

Running this will prompt you to set up authentication with GitHub, your class roster, and course details.

> [!WARNING]
> The GitHub Token (a password) will be stored in a plain-text config file and also be briefly exposed when being used. This isn't good practice but will suffice for a single-user safe machine.

## Typical Workflow

For this example:
- We want to make an assignment for a lab activity named "Lab1-Intro".
- Our GitHub organization is called "BME-2310"
- We made a folder on our local machine called "msoe_bme_2310" (you must know the full path).


### Assignment Creation

Create a template repo in your organization.
Ensure the repo name ends in `-template` and is also configured as a template repository in its settings page.
In this example, we would name the template repo: `Lab1-Intro-template`.

Normally, you would clone this template to your personal machine and populate the template with whatever files you want the students to have.
For the sake of example, we will assume this has already happened.

Confirm the template is valid:

```bash
clsrm show-templates
```

You should see the `Lab1-Intro-template` repo listed.

Now we are ready to mass-produce repositories for each student from the template repo with the `create-assignment` command:

```bash
clsrm create-assignment --dry-run Lab1-Intro-template
```

The `--dry-run` flag tells `create-assignment` to NOT actually create repositories yet - just simulate what *would* happen.

Once you are satisfied with the dry run, remove the flag to formally create the student assignment repositories:

```bash
clsrm create-assignment Lab1-Intro-template
```

Students will now see the repo in tools like GitHub Desktop or on the GitHub organization page.


### Assessment

After students submit their work by committing and pushing to GitHub, you can mass-clone them to your machine using the `clone` command.

#### Clone Repositories

Change your terminal's working directory to your `msoe_bme_2310` (`course-dir`) folder.

To clone an assignment we refer to the template repo's name but without the `-template`:

```bash
clsrm clone Lab1-Intro
```

This creates a folder in `msoe_bme_2310` titled `Lab1-Intro` and clones each student's repository into that folder.

Change directory into that folder:

```bash
cd Lab1-Intro
```

The working directory is now an 'assignment'.
`clsrm` has assignment-level commands that are easiest if you working directory is an assignment rather than the course.

#### Optional: Build Source

If using PlatformIO as the toolchain manager, you can build all repositories to check if they actually build.

```bash
clsrm build
```

You will get output stating which student repositories failed to build.

#### Assessment

To begin the assessment process, `clsrm` can create an `assessment` branch (the default name) in all of the repositories:

```bash
clsrm branch
```

The repositories cloned to your machine now have the `assessment` branch checked-out.
Any edits you make in their repos will not be applied to their `main` branch.
You can also add new files to their repo.

To view all repositories in VS Code (or whatever editor you configured):

```bash
clsrm open-all
```

> [!IMPORTANT]
> `open-all` is only really good for viewing and editing source code.
> Because the working directory is one above the actual repo, some build commands may not work (i.e., PlatformIO since it assumes VS Code's working directory is the repo).

With the `assessment` branch active, you can edit files in the student's repo or add feedback files.

After making edits and providing feedback (perhaps by adding a `feedback.md` file to their repo), you can mass-commit and push all repos with:

```bash
clsrm push
```

The `push` command does two things:
1. It commits all of your changes automatically with a default message "Assessment".
2. Pushes those commits to GitHub.

This also has a `--dry-run` flag to see what edits have been made and what will be committed:

```bash
clsrm push --dry-run
```

Students can visit their repo on GitHub and change their active branch to `assessment` to view your assessment commit.
